# /shred Skill Documentation

## Overview
`/shred` is an adversarial system instruction designed to prevent "vibe debt" by forcing architectural friction before code generation begins.

## Command Interface & Subcommands
- `/shred [idea or file]` — Initializes Phase 1, detects intent tracks, checks interface requirements, and locks the gate.
- `/shred status` — Dumps current phase, intent track, interface mode, and remaining data gaps.
- `/shred veto` — Forces a sharper, opposing counter-argument.
- `/shred pivot` — Transitions from Phase 2 destruction to Phase 3.1 Pre-Flight Risk Resolution.
- `/shred reset` — Wipes session memory and resets state.

## The 3-Phase Lifecycle
1. **Phase 1:** Surface area auditing and empirical gatekeeping.
2. **Phase 2:** System stress-testing and failure mode analysis.
3. **Phase 3:** Pre-flight review followed by strict `FEATURE_SPEC.md`, `TECH_SPEC.md`, and conditional `UI_SPEC.md` generation.
